## 3. 生产故障的完整因果链（旧 Pi 会话）

时间线全部来自旧会话 jsonl（`sessions/...2026-10-11T07-54-02-333Z_*.jsonl`，只读）：

1. 12:17:30 — Pi 在**自己的 assistant 正文**里写出了这句 git 上下文标签串（作为上一轮调查的结论）。
2. 12:21:06 — 下一次请求 → `11128`（requestId `33c6b785-…`）。
3. 12:24:05 — 重试 → `11128`（requestId `06b0e655-…`）。
4. 12:25:46 — 切换到 workbuddycn + 18080 → 仍 `11128`（同一份被污染历史被重放）。

即：**不是模型故障、不是渠道故障、不是网关故障，而是会话历史被写入触发串后自我持续**。
与 11148 的空工具名块「越重试越坏」是同一类病理（都会随历史重放而固化）。

## 6. 交接与预防规则（新增，后续 Agent 必读）

1. **禁止原样复述触发串。** 在 assistant 正文、handoff 摘要、诊断对话、提交信息中，一律使用
   「git 上下文标签串」或等价描述性代称。这是**运行时硬约束**：写进 assistant 正文就会污染当前会话。
   引用历史文档时也不要整段粘贴，只引用文件与章节。
2. **调查取证优先脱敏 + 局部探测 + 只读。**
   - 用最短载荷（如 `max_completion_tokens=8`）、最小探测次数验证假设；
   - 不开启会落全量提示词/对话的详细日志；
   - 不在正在使用的 Pi 会话里做「把可疑串打出来试试」这类实验——那正是本次事故的成因。
3. **排查顺序：先看历史，再看管道。** 遇到上游 400/重复失败，第一步检查
   **会话历史里是否已包含会被上游拦截的内容**（assistant 正文优先），而不是先怀疑模型、渠道或 Gateway。
   判据：换模型/换 provider/换端点后仍以同一错误码失败，且失败可随「换新会话」消失 → 高度指向历史污染。
4. **不要用「重试」验证渠道。** 重放同一份被污染的历史只会得到同样的 400；验证渠道应换干净会话 + 最小载荷。
5. **适用范围要写清，不得泛化。** 本次根因只解释：
   - 携带该 git 上下文标签串的请求（无论来自 ZCode 还是 Pi 自己写下）；
   - 在 buddy / workbuddycn / codebuddy 渠道上。
   它**不能**解释所有 11128：Claude Code 身份整句是**另一条独立指纹**；
   11133（参数非法）、11148（工具配对/空名块）、11151（空 content）等是不同错误码、不同成因。
6. **同一错误码可能多因。** 汇报时区分「已证实成因」与「同码但未证实成因」，不合并结论。
